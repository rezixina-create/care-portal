# Care Portal 企画・開発履歴記録書 (要件指示と実装の変遷)

本書は、介護施設向け統合業務ポータルシステム「Care Portal」の企画立ち上げから現在に至るまで、ユーザー（発注・監修者）が提示した要件・指示と、それに対して開発AI（Antigravity）および検証AI（Claude Code）がどのように設計・実装・改修を行ってきたかを時系列および機能別に記録した公式開発ログである。  
企画終了まで、新たな要件および変更が発生するたびに末尾へ追記・更新を継続する。

---

## 1. 開発概要と運用体制

### 1.1 システム概要
- **システム名称**: 介護施設 統合業務ポータルシステム (Care Portal)
- **対象施設**: 特別養護老人ホーム、介護老人保健施設、グループホーム等の介護保険施設
- **技術構成**:
  - フロントエンド: HTML5 / CSS3 / Vanilla JavaScript (SPA構成、外部フレームワーク非依存)
  - サーバー環境: PowerShell HTTP Server (`server.ps1`) / Python Server (`server.py`)
  - データ永続化: JSON形式データベース (`portal_database.json`)、自動世代バックアップ機構
  - ネットワーク基盤: Cloudflare Quick Tunnel (`cloudflared.exe`) による端末間暗号化通信
  - 可搬性: USBメモリ直下からのワンクリック起動 (`Care Portal 起動 (クリック).bat`)

### 1.2 協調開発体制
- **ユーザー (現場監修・要件統括)**:
  介護現場の実務経験に基づき、実態に即した業務フロー、帳票仕様、監査基準、UI配置、使い勝手の要件を指示。
- **Antigravity (開発AI)**:
  ユーザーの指示に基づき、画面設計、入力UI、帳票生成、内部ロジック、データ構造、APIエンドポイントの新規実装を担当。
- **Claude Code (実機検証・医学/監査基準照合AI)**:
  実際のサーバー・ブラウザ環境における動作確認、不具合修正、医学的裏付けのない記述の適正化、公的監査要件（改ざん防止・取消履歴化）の改修を担当。

### 1.3 開発における確立ルール
1. **誇張表現の排除**: システム解説やステータスにおいて過度な表現を用いず、客観的・事実ベースの表記を徹底。
2. **絵文字の全廃**: 公的記録システムとしての品位および端末間レンダリング崩れ防止のため、絵文字を一切排除。
3. **公的監査対応（記録の取消化）**: 介護・医療分野における記録改ざん防止の観点から、登録済み記録の物理削除を廃止し、取消理由・担当者・日時を伴う「取消・訂正履歴」として保持。
4. **架空例文の自動登録禁止**: 現場データに未確認のサンプル文章やダミー数値が自動混入することを防止。

## 2. 時系列開発履歴（ユーザー指示と実装内容）

### フェーズ1: 企画構想・要件定義と基本骨格の策定 (2026-09-30)

#### ユーザーからの提示内容・指示
- 単独のExcelや手書き記録ではなく、文字検索や時系列（何月何日何時）で検索・把握できる仕組みを作りたい。
- 職員全員がPCやタブレットから共有して記入・閲覧できるWeb形式にしたい。
- 外部の無関係な人には見せず、施設職員のみが利用できる環境にしたい。
- 介護記録だけでなく、取引先・仕入れ・物品消費・在庫管理も一元化したい（kintoneのようなイメージ）。
- 利用者の物品購入・消費と在庫を連動させ、在庫低下時に「補充が必要です」とアラートを出したい。
- 利用者の病歴をクリックすると詳細な症状や留意点を参照できるようにしたい。
- 介護現場の実態に即した機能（口腔ケア・義歯管理、入浴チェック表・備考欄の処置薬、服薬直前の確認・頓服記録、受診時特記、ケアプラン、預り金と請求の分離、非常食の賞味期限アラート、利用者の誕生月事前告知など）の洗練。
- 介護現場ではオムツを枚数ではなく「袋」単位で管理・請求すること、誤入力時の修正対応など。

#### 実装・対応内容
- HTML/CSS/Vanilla JSによるSPA構成を設計。
- メインナビゲーションとして「介護ポータル」と「事務ポータル」の2大区分を策定。
- 利用者カルテ（基本情報、病歴、服薬、アレルギー、要介護度等）およびタイムライン形式の介護記録機能を実装。
- 物品・在庫管理システム（品目マスタ、在庫数追跡、最低在庫アラート、入出庫計算）を構築。
- ローカルWebサーバーおよびJSONデータベース（`portal_database.json`）によるデータ管理構造を確立。
